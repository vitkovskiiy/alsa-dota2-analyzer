# Ухвалення рішення щодо вибору веб-фреймворку (Fastify vs Express)

## Контекст (Context)
Проєкт Alsa потребує швидкого та надійного REST API для обробки великих масивів даних (статистика матчів, синергія героїв, вінрейти). Нам потрібно вибрати фреймворк для Node.js, який зможе впоратись із навантаженнями обчислень та віддавати JSON максимально швидко.

## Розглянуті варіанти (Alternatives)
1. **NestJS** — потужний, але занадто "важкий" і потребує багато бойлерплейт-коду. Не підходить для швидкого MVP та мікросервісного підходу в рамках лаби.
2. **Express.js** — стандарт індустрії, величезне ком'юніті, але стара архітектура (відсутнє вбудоване повернення Promise/async-await без милиць), досить повільний у серіалізації JSON.
3. **Fastify** — сучасний, мінімалістичний фреймворк, орієнтований на продуктивність. Має вбудовану валідацію через JSON Schema і працює "з коробки" з async/await.

## Рішення (Decision)
Ми обрали **Fastify**.

## Обґрунтування (Justification)
- **Продуктивність:** Fastify є одним із найшвидших фреймворків для Node.js, що критично для сервісу, який обчислює статистику "на льоту".
- **DX (Developer Experience):** Повна підтримка TypeScript та відмінна екосистема плагінів. Вбудований логгер (Pino) працює надзвичайно швидко.
- **Відповідність вимогам:** Легко зв'язується з PrismaORM, що використовується в проєкті.

## Наслідки (Consequences)
- **Позитивні:** Зменшено overhead на серіалізацію/десеріалізацію JSON. Код чистіший завдяки нативній підтримці асинхронності.
- **Негативні:** Екосистема менша, ніж у Express (деякі специфічні middleware доведеться адаптувати або писати самостійно).
- **Ризики:** Крутіша крива навчання для нових розробників порівняно з базовим Express. Коригується зрозумілою документацією.
