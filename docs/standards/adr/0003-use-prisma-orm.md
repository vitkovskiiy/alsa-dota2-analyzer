# ADR 0003: Prisma як ORM

- **Статус:** прийнято
- **Дата:** 2026-10-22

## Контекст

Сервер написаний на TypeScript і працює з PostgreSQL. Потрібно описати моделі `Hero`, `Match`, `MatchHero`, `HeroPair`, виконувати транзакційний запис, версіонувати зміни схеми й отримувати типи запитів, узгоджені з моделлю даних.

## Розглянуті варіанти

| Варіант      | Переваги                                                                                                                                      | Недоліки                                                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Prisma       | Схема як окреме джерело опису моделей, згенерований TypeScript-клієнт, міграції та високорівневі операції `include`, `upsert`, `$transaction` | Потрібна генерація клієнта; складні специфічні SQL-запити можуть вимагати raw SQL                                                       |
| Drizzle ORM  | SQL-подібний стиль, типи виводяться зі схеми TypeScript, легше контролювати SQL                                                               | Схема описується в коді, а абстракція ближча до SQL; для цієї роботи це означало б більше ручного опису запитів і міграційного workflow |
| TypeORM      | Зрілий ORM із репозиторіями та сутностями                                                                                                     | Декораторні entity та конфігурація додають структури, які не потрібні невеликому API                                                    |
| `pg` без ORM | Прямий контроль над SQL і драйвером                                                                                                           | SQL, мапінг рядків у типи та узгодження змін схеми з кодом підтримуються вручну                                                         |

## Рішення

Використовувати **Prisma ORM 7** разом із PostgreSQL. Prisma описує моделі й генерує TypeScript-клієнт; PostgreSQL лишається відповідальною за зовнішні ключі, унікальність і транзакційну цілісність. + have exp in usage prisma

## Обґрунтування

- Моделі й відношення проєкту видно централізовано в `prisma/schema.prisma`.
- Згенерований клієнт типізує поля та аргументи запитів для TypeScript-коду.
- Міграції зберігаються у репозиторії, тому зміни схеми можна відтворити в іншому середовищі.
- `$transaction` відповідає сценарію атомарного створення матчу та його складу.
- `upsert` спрощує повторюване заповнення довідника seed-скриптом.

Це аргументи відповідності потребам цього проєкту, а не твердження, що інші ORM не мають типізації, міграцій чи транзакцій.

## Наслідки та обмеження

- Зміни моделей потребують оновлення міграцій і Prisma Client.
- Unit-тести з моками перевіряють поведінку застосунку, але не підтверджують, що згенерований запит працює на PostgreSQL.
- Важкі або специфічні SQL-запити за потреби можна виконувати параметризованим raw SQL, вимірявши їхню користь.
- Конфігурація Prisma 7 для CLI зберігає URL підключення в `prisma.config.ts`.
