# ADR 0002: PostgreSQL як тип бази даних

- **Статус:** прийнято
- **Дата:** 2026-10-21

## Контекст

Застосунок зберігає матчі, героїв, склад кожного матчу та агреговану статистику пар героїв. Матч пов'язаний із багатьма героями, а кожен герой бере участь у багатьох матчах. Створення матчу та всіх його записів складу має бути атомарним. Локальне середовище має відтворюватися командою Docker Compose.

## Розглянуті варіанти

| Варіант              | Переваги                                                                        | Недоліки                                                                                                                                    |
| -------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| SQLite + Prisma      | Мінімальне налаштування, база у файлі                                           | Для цієї лабораторної потрібна спільна PostgreSQL-сумісна БД; конкурентний запис і продакшн-подібне середовище довелося б перевіряти окремо |
| MongoDB + Mongoose   | Гнучка структура документів                                                     | Наші зв'язки матчів, героїв і складів потребують транзакцій та з'єднань; документна модель їх не спрощує                                    |
| PostgreSQL + Prisma  | Реляційні обмеження, транзакції, індекси, керовані міграції, типізований клієнт | Потрібен окремий процес PostgreSQL                                                                                                          |
| PostgreSQL + raw SQL | Повний контроль над SQL                                                         | SQL, мапінг результатів, типи та міграції доводиться підтримувати вручну                                                                    |

## Рішення

Використовувати **PostgreSQL 16** як реляційну СУБД. ORM обирається окремо в [ADR 0003](0003-use-prisma-orm.md). Локальна БД запускається через Docker Compose.

## Обґрунтування

- Зовнішні ключі гарантують, що склад матчу посилається на наявні матч і героїв.
- Унікальні індекси на `Match.externalId`, `MatchHero(matchId, heroId)` та `HeroPair(hero1Id, hero2Id)` захищають від дублікатів.
- Транзакція навколо створення матчу й `MatchHero` не залишає частково записаний матч, якщо вставка складу не вдається.
- `HeroPair` і зв'язки моделі відповідають структурі статистики синергії.

## Наслідки та обмеження

- Розробнику потрібен запущений Docker Engine або доступний PostgreSQL.
- Доступ до БД потрібен для міграцій, seed та інтеграційної перевірки; unit-тести з моками цього не замінюють.
- Застосунок має коректно обробляти помилки запису й конфлікти унікальності.
